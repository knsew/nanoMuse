# nanoMuse 1.1.1 · Beacon

🐉 **nanoMuse `1.1.1` "Beacon"**: a patch release, hours after Harbor. 1.1.0's Android release build failed on R8, so the release shipped without an APK; 1.1.1 fixes the build and completes the release.

The Docker image and the harness bundle from 1.1.0 were fine, and they are rebuilt from this tag with nothing but the version bump. The only change in 1.1.1 is the one line the Android build needed: a ProGuard rule telling R8 that the java.beans classes SnakeYAML references do not exist on Android. Everything else in this release is Harbor's, with the APK, the desktop installers and the Docker image all built from tag `v1.1.1`.

## Highlights

- **The Android release build works again.** SnakeYAML, used for skill-frontmatter parsing, references java.beans classes through reflection; they do not exist on Android, and R8 failed the release build on the missing classes. A ProGuard rule silences the warnings, and the APK is built and signed in CI as 1.1.0's was meant to be.
- **The release is complete this time.** 1.1.0 shipped the Docker image and the harness bundle but no APK, and the desktop Linux build stalled on its runner; 1.1.1 ships all of them from one tag.

## Upgrade Notes

- **Android does not install over the upstream build.** `nanoMuse-1.1.1-arm64.apk` (Android 8.0+, arm64; versionCode 54) is signed with this fork's own key, certificate SHA-256 `91:3A:48:A6:62:C3:CC:F7:F2:83:C3:4D:D5:F5:FC:EB:9C:4C:9B:85:86:48:BE:7D:CC:79:8D:59:0A:CD:98:4B`, not the upstream key. If you run the upstream app, uninstall it first; your relay keeps your conversations, so they come back when you sign in again. Within this fork, every version uses the same key and installs over the last. Verify with `sha256sum -c nanoMuse-1.1.1-arm64.apk.sha256`.
- **The desktop installers are built by CI from the tag `v1.1.1`.** Windows and Linux only; this fork no longer builds macOS or iOS. The Windows package is not signed: click *More info* and *Run anyway* once. On Linux prefer the `.deb`; the AppImage needs FUSE (`--appimage-extract-and-run` without). They arrive a little after the APK, and `SHA256SUMS-desktop.txt` lists every checksum.
- **The relay is 0.32.0, unchanged.** Nothing in this release touches the relay; if you already run 0.32.0, there is nothing to do. [cloud/README.md](https://github.com/knsew/nanoMuse/blob/main/cloud/README.md) has the details.
- **The relay address is required, with no official default.** Every client asks for your relay's address at setup; there is no hosted relay to fall back to.
- **Where to get it.**

  | | |
  |---|---|
  | Android 8.0+, arm64 | `nanoMuse-1.1.1-arm64.apk` |
  | Windows 10+ | `nanoMuse-Desktop-1.1.1-win-x64.exe` (the desktop app, on DeepSeek Harness; not signed) |
  | Linux x64 | `nanoMuse-Desktop-1.1.1-linux-x64.deb` (preferred) / `.AppImage` (needs FUSE; `--appimage-extract-and-run` without) / `.tar.gz` (unpack anywhere, run `./nanomuse-desktop`) |
  | DeepSeek Harness Desktop you already run | `dsh-nanomuse-1.1.1.tgz`, `dsh plugin --profile desktop add …` ([how](https://github.com/knsew/nanoMuse/blob/main/harness/README.md)) |
  | Docker | `ghcr.io/knsew/nanomuse:1.1.1` (also `:1.1` and `:latest`), the runtime with the web console on port 8787 |
  | Your own relay | `bash scripts/self-host.sh`, [docs/self-hosting.md](https://github.com/knsew/nanoMuse/blob/main/docs/self-hosting.md) |

## Community

This fork is kept for private use: one household, its own relay, its own model. There is no official service behind it, no account with anyone, no allowance, and nothing to sign up for. You bring a relay and a model endpoint, and the apps point at them. The source is GPL-3.0-or-later, and the work it builds on is the upstream project, [nano-muse/nanoMuse](https://github.com/nano-muse/nanoMuse).
