# nanoMuse 1.1.0 · Harbor

🐉 **nanoMuse `1.1.0` "Harbor"**: the first release of this fork, and a private-deployment release. The hosted service is gone from the source: no telemetry, no update checks, no multi-tenant relay, and the relay and the model defaults point at a self-hosted relay and a local endpoint.

This fork is kept for one household's own use. It builds on the upstream tree past 1.0.9 and removes everything that talks to the official service, so the whole thing runs on hardware of your own: the relay in a container, the model on a local endpoint, the apps pointed at your relay. Nothing in this build talks to the official nanoMuse service: there is no account with it, no telemetry to it, and no update check against it. The desktop is built for Windows and Linux only, and the Android release APK is signed in CI with the fork's own key.

## Highlights

- **The hosted service is gone from the source.** Telemetry uploads, the four update checkers, and the multi-tenant relay modules (invites, allowances, review codes, GitHub stats, GeoIP, Aliyun SMS, star nudges, the DashScope media proxy) are removed, with the demo, docs-site and showcase directories. The audit is PRIVATE-DEPLOY-ANALYSIS.md.
- **The relay and the model default to your own hardware.** The relay address is required at setup, with no official default; the model default is a local OpenAI-compatible endpoint. Bring your own relay and your own model; nothing else is assumed.
- **Device conversations on Android and desktop.** A chat can be bound to one device, with its context saved and recovered after a reconnect; offline or older devices keep a selectable route for drafts, without local fallback or automatic resend. For #815.
- **Long turns keep their context.** The request stays in view during long turns, and the turn after a long one keeps the previous request and the newest work, so "carry on" arrives with something to carry on from.
- **Sensitive actions are not repeated blindly.** A completed sensitive action stays in view after limits trim the turn, and the runtime asks before repeating an identical sensitive action in the same conversation, including after a cancellation left the outcome unknown. For #938.
- **The Levea video editor joins the connector catalogue.** For desktop and phones, with OAuth sign-in.

## Upgrade Notes

- **Android does not install over the upstream build.** `nanoMuse-1.1.0-arm64.apk` (Android 8.0+, arm64; versionCode 53) is signed with this fork's own key, certificate SHA-256 `91:3A:48:A6:62:C3:CC:F7:F2:83:C3:4D:D5:F5:FC:EB:9C:4C:9B:85:86:48:BE:7D:CC:79:8D:59:0A:CD:98:4B`, not the upstream key. If you run the upstream app, uninstall it first; your relay keeps your conversations, so they come back when you sign in again. Within this fork, every version uses the same key and installs over the last. Verify with `sha256sum -c nanoMuse-1.1.0-arm64.apk.sha256`.
- **The desktop installers are built by CI from the tag `v1.1.0`.** Windows and Linux only; this fork no longer builds macOS or iOS. The Windows package is not signed: click *More info* and *Run anyway* once. On Linux prefer the `.deb`; the AppImage needs FUSE (`--appimage-extract-and-run` without). They arrive a little after the APK, and `SHA256SUMS-desktop.txt` lists every checksum.
- **The relay is 0.32.0.** The multi-tenant modules are gone: invites, allowances, review codes, SMS sign-in, GitHub stats, GeoIP, star nudges, and the DashScope media proxy. Sign-in is by email code. If you run a self-hosted relay, pull the new image and restart it; your accounts and conversations stay in the relay's database. [cloud/README.md](https://github.com/knsew/nanoMuse/blob/main/cloud/README.md) has the details.
- **The relay address is required, with no official default.** Every client asks for your relay's address at setup; there is no hosted relay to fall back to.
- **Where to get it.**

  |---|---|
  | Android 8.0+, arm64 | `nanoMuse-1.1.0-arm64.apk` |
  | Windows 10+ | `nanoMuse-Desktop-1.1.0-win-x64.exe` (the desktop app, on DeepSeek Harness; not signed) |
  | Linux x64 | `nanoMuse-Desktop-1.1.0-linux-x64.deb` (preferred) / `.AppImage` (needs FUSE; `--appimage-extract-and-run` without) / `.tar.gz` (unpack anywhere, run `./nanomuse-desktop`) |
  | DeepSeek Harness Desktop you already run | `dsh-nanomuse-1.1.0.tgz`, `dsh plugin --profile desktop add …` ([how](https://github.com/knsew/nanoMuse/blob/main/harness/README.md)) |
  | Docker | `ghcr.io/knsew/nanomuse:1.1.0` (also `:1.1` and `:latest`), the runtime with the web console on port 8787 |
  | Your own relay | `bash scripts/self-host.sh`, [docs/self-hosting.md](https://github.com/knsew/nanoMuse/blob/main/docs/self-hosting.md) |

## Community

This fork is kept for private use: one household, its own relay, its own model. There is no official service behind it, no account with anyone, no allowance, and nothing to sign up for. You bring a relay and a model endpoint, and the apps point at them. The source is GPL-3.0-or-later, and the work it builds on is the upstream project, [nano-muse/nanoMuse](https://github.com/nano-muse/nanoMuse).

The complete corresponding source of this build is tag `v1.1.0` plus the `android/deps/proot` submodule ([nano-muse/proot](https://github.com/nano-muse/proot)); the desktop installers, the Android APK and the Docker image are built by CI from the same tag. The whole repository is GPL-3.0-or-later. nanoMuse Desktop carries DeepSeek Harness unmodified, with its licence files inside; *harness* in the name is the word, not DeepSeek's. The chat apps follow [nanobot](https://github.com/HKUDS/nanobot)'s design (MIT); the desktop's operator is ported from [UI-TARS-desktop](https://github.com/bytedance/UI-TARS-desktop) (Apache-2.0; `THIRD_PARTY_NOTICES.md`). nanoMuse is not affiliated with Meta; Muse is a trademark of Meta Platforms, Inc. 这个 fork 是给一家人自己用的。它在上游 1.0.9 之后的代码上，拿掉所有和官方服务打交道的部分，让整套东西跑在自己的机器上：中继装在容器里，模型走本地端点，应用指向自己的中继。这个版本里的任何东西都不和官方 nanoMuse 服务联系：不在它那里开账号、不向它发遥测、不找它检查更新。桌面端只构建 Windows 和 Linux 版，Android 正式版 APK 由 CI 用 fork 自己的密钥签名。

### 亮点

- **官方云已经从源码里拿掉。** 遥测上传、四个更新检查、多租户中继模块（邀请、额度、评审码、GitHub 统计、GeoIP、阿里云短信、星标提醒、DashScope 媒体代理）都删了，演示、文档站和展示目录也一起拿掉。审计见 PRIVATE-DEPLOY-ANALYSIS.md。
- **中继和模型默认都用自己的机器。** 设置时必须填中继地址，没有官方默认值；模型默认走本地 OpenAI 兼容端点。自己带中继和模型，别的什么都不假设。
- **Android 和桌面端有了设备对话。** 一次对话可以绑定一台设备，上下文会保存下来，重连后能恢复结果；离线或旧设备给草稿留了一条可选的路，不做本地回退也不自动重发。对应 #815。
- **长任务不再丢上下文。** 长轮次里请求一直可见，长轮次之后的那一轮保留上一次的请求和最新的工作，所以「继续」来的时候有东西可继续。
- **敏感操作不会被盲目重复。** 轮次被截断后，已完成的敏感操作和文件写入还在视野里；同一个对话里重复一个一模一样的敏感操作之前，运行时会先问一声，取消后结果不明时也一样。对应 #938。
- **Levea 视频编辑器加入连接器目录。** 桌面端和手机都有，用 OAuth 登录。
